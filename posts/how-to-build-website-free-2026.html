How I Built My Website for Free in 2026 (Step-by-Step)

Published: October 10, 2026 | Reading time: 8 minutes

Two weeks ago, I had zero websites. Today, I have one running — and it costs me exactly nothing per month.

Sound too good to be true? I thought so too when a friend first told me about this. But it works. And in this post, I'm going to show you exactly what I did — no tech jargon, no skipped steps.

Full disclosure: I'm not a developer. I don't know how to code from scratch. I started this whole thing by copying and pasting code someone else wrote. So if I can do it, you definitely can.

The bottom line: You need a domain (about $10/year) and nothing else. Hosting, SSL, CDN — all free. Forever.

Why I Even Started This

I got tired of paying for hosting. I had a small blog before this, and I was paying around $12/month just to keep it online. That's $144 per year. Not a lot, but why pay when there's a free option that works better?

Then I read about GitHub Pages. I was skeptical. "Nothing is really free," I thought. But I tried it anyway, and three hours later I had a live site. No catch. No hidden limits. Just a working website.

What You Will Need

Before we start, make sure you have:

  • A computer or even just a smartphone (I did everything on my phone)
  • An email address
  • About 1-2 hours of time
  • Optional: a domain name (about $10/year)

That's it. No credit card needed for the free parts.

Step 1: Create a GitHub Account

Go to github.com and sign up. It takes 2 minutes.

Pick a username you actually like, because it becomes part of your website URL. I picked mine quickly and now I regret it a bit — so take your time here.

You'll need to verify your email. Don't skip this step.

Step 2: Create a Repository

Once you're logged in, click the "+" button in the top right and select "New repository."

Here's what to fill in:

  • Repository name: Anything you want (like "my-site" or "blog")
  • Description: Optional, but nice to have
  • Public: Choose this — required for free hosting
  • Add a README file: Check this box

Then click "Create repository." Done.

Step 3: Add Your First File

This is where most people get stuck. But it's actually easy.

Inside your new repository, click "Add file" → "Create new file."

Name it exactly: index.html

Then paste this basic code:

<!DOCTYPE html>
<html><body>
<h1>My First Website</h1>
<p>Hello world!</p>
</body></html>

Click "Commit changes" at the bottom.

Boom. You just created your first web page. Honestly, the first time I did this, I was surprised at how simple it was.

Step 4: Turn On GitHub Pages

Now the magic part.

  1. Go to your repository's Settings
  2. Scroll down to "Pages" in the left menu
  3. Under "Source," choose "Deploy from a branch"
  4. Select "main" branch and "/ (root)" folder
  5. Click "Save"

Wait 2-3 minutes. Your site is now live at:

yourusername.github.io/repository-name

I remember checking mine five times thinking something was wrong. It just took a few minutes to show up.

Step 5: Get a Custom Domain (Optional But Recommended)

Your GitHub URL works fine, but it looks unprofessional. Something like myusername.github.io/blog isn't great for sharing.

For about $10 per year, you can buy your own domain. I got mine from Namecheap, but any registrar works.

Once you have a domain, you'll need to point it to GitHub. This involves adding a few DNS records — and yes, I had to Google what DNS records actually are.

Quick version: you add four "A records" with specific IP addresses, plus a CNAME for the www version. GitHub has a guide for this, but it took me about 30 minutes to figure out the first time.

After that, wait about 30 minutes for it to propagate. Then update the Custom Domain field in your GitHub Pages settings.

Step 6: Add SSL (Free Security)

Once your custom domain works, scroll down in GitHub Pages settings and check the "Enforce HTTPS" box.

This gives you a free SSL certificate, which means your site shows a padlock in browsers. Trust matters, and this helps a lot.

It took about 15 minutes for mine to become available. If yours doesn't show up right away, just refresh the page after a while.

What I Do Now to Manage the Site

All my files live in the GitHub repository. When I want to add a new post, I create a new HTML file, commit the change, and it goes live automatically.

I edit everything on my phone using Termux (a terminal app for Android). It's not for everyone — most people just use GitHub's web interface, which works great too.

Either way, the process takes about 5 minutes per new post once you get used to it.

Total Cost Breakdown

Just to be clear about what this actually costs:

  • Domain: $10-15 per year
  • Hosting: $0
  • SSL: $0
  • CDN (Cloudflare): $0
  • Total monthly: About $1

Compare that to WordPress hosting which starts at $5-10 per month for basic plans. That's $60-120 per year.

I'm not saying GitHub Pages is right for everyone. If you need WordPress features, e-commerce, or complex databases, you'll need paid hosting. But for a simple blog, portfolio, or informational site? This works perfectly.

Common Issues I Ran Into

Nobody talks about the problems, so let me share mine:

Problem 1: My site showed a 404 error

Turned out my file wasn't named exactly "index.html." Capital letters matter. "Index.html" won't work.

Problem 2: Custom domain kept failing

I had proxy mode on in Cloudflare. It needed to be DNS-only during setup. Took me hours to figure out.

Problem 3: SSL wasn't available

Just needed to wait. About 20 minutes after the DNS propagated, the Enforce HTTPS option appeared.

Should You Try This?

If you're asking me? Yes, absolutely. Even if you end up moving to paid hosting later, you'll learn how websites work. That knowledge is worth the 1-2 hours it takes.

The only reason not to do this is if you need advanced features. But for 90% of personal sites and blogs, this is more than enough.

Frequently Asked Questions

Q: Is GitHub Pages really free forever?

Yes. GitHub has offered free Pages hosting since 2008. It's part of their core product. No sign of that changing.

Q: Can I use this for a business site?

Yes, but check GitHub's terms. Commercial sites are allowed as long as they're not primarily for e-commerce transactions.

Q: How much traffic can it handle?

Soft limit is 100 GB bandwidth per month and 1 GB site size. For most sites, this is way more than enough.

Q: Can I use WordPress with this?

No, not in the traditional sense. GitHub Pages only hosts static HTML/CSS/JS. If you need WordPress, use paid hosting.

Q: Do I need to know how to code?

For a basic site, no. You can use HTML templates and just edit text. For advanced features, some coding helps.

What I Got Wrong on My First Website

My first attempt at a free website was a disaster. I want to share the mistakes so you do not repeat them:

Mistake 1: I picked a random username for GitHub - something like "user_2847593" - not realizing it would become part of my site URL. Now I am stuck with it. Pick a username you actually like.

Mistake 2: I named my file "Index.html" with a capital I. It took me 2 hours to figure out why the site was showing a 404 error. Filenames are case-sensitive.

Mistake 3: I bought the wrong domain extension first - .xyz instead of .online. The .xyz domain was cheap but not professional. I ended up buying a second domain.

Mistake 4: I enabled Cloudflare proxy before GitHub had verified my domain. This caused 3 days of SSL issues. The correct order is: DNS-only first, verify with GitHub, then enable proxy.

Mistake 5: I uploaded 50 blog posts at once without checking a single one. Two of them had broken links and one had a wrong phone number. Always test before bulk uploading.

Every mistake took at least an hour to fix. If you avoid them, you will save yourself 5-6 hours of frustration.

Why I Still Recommend This Approach

Despite the mistakes, here is why GitHub Pages is still the best free option in 2026:

  • Truly free: Not "free trial" or "free for 30 days" - actually free forever
  • Fast: Hosted on global CDN servers
  • Reliable: 99.9% uptime, backed by Microsoft
  • Secure: Automatic HTTPS, DDoS protection
  • Scalable: Handles viral traffic without breaking
  • Educational: You learn actual web development concepts

The only real limitation is that it is static-only. No PHP, no databases, no server-side code. But for blogs, portfolios, and informational sites, this is not a problem.

Advanced Features You Can Add Later

Once you are comfortable with the basics:

  • Custom 404 page: Replace the default GitHub 404 with your own
  • Analytics: Add Google Analytics or Cloudflare Analytics
  • Contact form: Use Formspree, Netlify Forms, or Google Forms
  • Comments: Disqus or Utterances
  • Search: Add a simple JS-based search
  • Sitemap: XML sitemap for Google indexing
  • PWA support: Turn it into a Progressive Web App

Each of these takes 15-30 minutes and makes your site more professional.

Final Thoughts

I'll be honest — building my first website felt intimidating. Every tutorial I read assumed I knew things I didn't. But once I just started doing it, everything clicked.

If you've been thinking about building a site but keep putting it off, just start. Make the GitHub account today. Create that first file. You'll be surprised how quickly you get the hang of it.
